# ZGW to ELC classic CAN contract (source review, 2026-10-17)

This is the source contract used for the ELC changes in this tree. It is not a measured bus trace. The ZGW source is read from `D:/GitHub_Repos/ZGW/ZGW/ZGW_APP`; only ELC files are changed.

| Direction | ID / DLC | Source and meaning | ELC behavior |
| --- | --- | --- | --- |
| ZGW to ELC | `0x3FF` / 1 | `BSW/Com/CanIf/CanIf.c` and `BSW/Com/Com.c`: NM3 byte 0 is PN1. `APP/GatewaySwc/GatewaySwc.c` defaults the byte to `0xFF`. COM schedules NM3 every 20 nominal 5 ms ticks. ZGW `CanNm.c` is its local transmitter; it does not define subordinate reception semantics. | Accept only standard data frame DLC 1. Existing ELC telemetry uses bit 6. Treat bit 6 as the ELC application communication request. Preserve the whole byte for observation; other bits are not interpreted as ELC requests. Stop application TX on cleared bit 6 or 200 ticks without a frame. Keep CAN RX and diagnostics available. |
| ZGW to ELC | `0x050` / 2 | `GatewaySwc_GenerateCanOutputs`, `Com.c`, ZGW DBC: alive counter bits 0..3, data ID bits 4..6 (`7`), request bit 7, byte 1 is low byte of reflected CRC32 over `[alive, request, dataId]`, seed `0xFFFFFFFF`, final inversion. Mixed TX has 200 tick period. | Reject wrong DLC/data ID/CRC and invalidate the prior command on an invalid frame. Valid request 0/1 drives `SMon_CmdStat` via COM. After 200 nominal 5 ms ticks without a valid request, command is 0. Do not extend validity on corrupt data. |
| ELC to ZGW | `0x051` / 1 | `CanIf.c`, `Com.c`, DBC: bit 0 is LoadStatus; ZGW receive deadline is 1005 ms. | Report `SMon_L1ST` bit 0 on change and every 100 nominal 5 ms ticks while ELC application communication is enabled. Retry failed submission. |
| ZGW to ELC | `0x3A0` / 1 | ZGW DBC `VehicleState`, bits 0..3 `VehicleStatus`; ZGW COM schedules mixed mode with 20 tick period. | Preserve legacy application interpretation of values 0..6, reject reserved high nibble and values above 6, and clear the application mirror on invalidity or expiry. The DCM programming gate reads the currently valid value. Missing-frame diagnosis follows the 200-tick deadline after a valid frame; from FullCom startup without one, it starts after 201 ticks. The old ELC receive ID `0x097` does not match ZGW and is retired for this signal. |
| ELC to ZGW | `0x6EE`, `0x6EF`, `0x6F0` | ZGW DBC gives TempMeas and VoltageCurrent DLC 8 and I2T counter DLC 4, each with 5 ms cycle. | Keep existing ELC field encoding and cycle. Queue in COM, then PduR/CanIf/Can submit with retry on failed submission. |
| ELC to ZGW | `0x6F1`..`0x6F6` | ZGW DBC gives DLC 8 battery float pairs: charge/discharge Ah, coulomb/OCV SoC, hybrid SoC/SoH, capacity/resistance, average charge/discharge current, runtime/time to full. The DBC assigns 1000 ms to all except `0x6F5` at 5 ms. | Correct SoC frame placement. Retain the existing ELC 200 ms battery sampling cycle until live gateway receive timing is measured; COM buffers and retries each queued frame. |
| ELC to ZGW | `0x6F7` / 1 | ZGW DBC `BattDiagnosis` packs eight flags into bits 0..7. Legacy ELC emitted eight separate bytes. | Pack the seven directly corresponding ELC flags. Hold bit 2 (ZGW boolean `Confindence`) at 0 because ELC has a 0..100 percentage and no agreed boolean mapping. |

`ELC_APP/Src/can.c` keeps the bxCAN controller listening after initialization. No ZGW source establishes an ELC NM transmit ID, transceiver sleep protocol, or partial-network wake filter, so this implementation does not transmit NM or place bxCAN in hardware sleep on NM3 timeout. ELC `CanSM` controls upper-layer TX availability while keeping RX online and inhibits application TX when HAL reports the controller unavailable or bus-off. Diagnostics are not disabled by NM3 timeout.

ZGW `BSW/Com/CanNm/CanNm.c` defines 200 tick timeout, 40 tick repeat, 100 tick ready sleep and 40 tick prepare sleep for its **own** NM channel. These timings are not copied as an invented ELC sleep handshake. ELC records first-frame, requested, released, and timed-out states. The 200 tick ELC receive deadline matches the existing ELC implementation and exceeds the gateway nominal 100 ms period by 10x.

The routed diagnostic gap is now closed in ELC source: APP, resident FBL and RAM updater receive extended710/58 and respond/FC on710/F0, following ZGW CanTp's configured receive address. There is no normal702/703 fallback. Physical route/FC/response correlation remains unverified; see [current interoperability dependencies](../compatibility/ZGW_FCD_GAP_ANALYSIS.md).

Current COM confirmation semantics: successful submission starts an in-flight request; only physical TX success clears pending state. Failure retains it for retry, and version counters protect newer telemetry. A coherent SMon publication supplies telemetry. CRC-protected alive values are observed without an invented consecutive-counter rule, because ZGW generation and COM scheduling/repetition are independent. See [module coverage](../autosar/BSW_FUNCTIONAL_COVERAGE.md).
