# Current ELC diagnostics

The application uses `Can -> CanIf -> CanTp -> PduR -> Dcm`, with complete service payloads and the AUTOSAR TP buffer callbacks. The Dcm engine (`ELC_APP/BSW/Diag/Dcm/Dcm.c`) is table driven: services 10, 11, 14, 19, 22, 28, 31, 3E and 85 with session masks, minimum lengths and sub-function flags; DIDs and routines are tables in `Dcm_Cfg.c`; application data and reset policy are callouts in `ELC_APP/APPL/DcmAppl`. See [functional coverage](../autosar/BSW_FUNCTIONAL_COVERAGE.md), [alignment review](../autosar/AUTOSAR_LAB_ALIGNMENT.md) and [closure](../modernization/ELC_FUNCTIONAL_GAP_CLOSURE.md) for supported service/DID/RID details and exact validation status.

All target images receive extended-address CAN 710/58 and respond on 710/F0, matching ZGW's routed channel. Normal 702/703 is retired. Application sessions are default/extended with a vehicle-state 6 programming gate, S3 = 5 s, P2 = 50 ms and P2* = 5 s; `10 02` answers `50 02 00 32 01 F4` (and NRC 0x7E when requested outside the extended session). The generic engine applies NRC 0x11, 0x7F, 0x13 in that order, then the service handler returns 0x13/0x12/0x7E/0x31/0x14/0x22; sub-function services honor suppressPosRspMsgIndicationBit, negative responses are never suppressed. Asynchronous work answers NRC 0x78 after 40 ms and every 4.5 s. ClearDTC, reset and programming handover wait for NvM completion (a Dem write already running is waited for, not refused); response confirmation precedes reset. Failed Flash programming cannot yield a positive durable clear response.

DTC services use the DEM public interfaces. Qualified monitor failures/passes (`Dem_SetEventStatus`) retain identifiers 50..61, occurrence and the existing freeze-frame fields. Confirmation is one qualified failure; debounce remains with application monitors (PREPASSED/PREFAILED are rejected); aging is unconfigured. ReadDTCInformation 01/02/04/06 supports masks, snapshot record 1/FF and extended-data record 1/FF (the two-byte occurrence counter). Exact or FFFFFF snapshot selection is supported (the FFFFFF form is an ELC extension; strict ISO would answer NRC 0x31). Availability mask is 7F.

APP F101 returns six bytes: APP major/minor/patch followed by FBL major/minor/patch, as the inspected FCD/ZGW source expects. The legacy little-endian reset counter remains at F001; F180 remains ELC's four-byte version, and F100/F186 report active block/session. Existing raw-float snapshot encoding is retained. Not offered: SecurityAccess, WriteDataByIdentifier, IO control, functional addressing, NRC 0x21 (a request arriving while another is processed is dropped).

Resident and SRAM programming use two compiled instances of `ELC_FBL/Core/Inc/boot_protocol.h` (`BootTp_*` transport, `BootDcm_*` services); hardware Flash ports and execution environments remain distinct. See [current programming contract](../bootloader/PROGRAMMING_PROTOCOL.md). No physical session, reset or Flash programming was executed.
